## Objective
Create knowledge_extract.py: the Knowledge Factory's machine translation layer (Addendum E rev 2 §8, N3). For each documented strategy in knowledge_entries it asks an LLM to extract the source's rules into explicit fields, marking anything the source does not state as "unspecified" / "unknown" / "requires_interpretation" (never invented), and to write a clearly labelled Stockbot interpretation in the project's genome grammar. The result is validated and stored beside the original text. Plus its regression test.

## Background
knowledge_entries (existing table) columns used here: entry_id, source, strategy_name, strategy_family, source_type, source_title, source_author, source_url, original_claim, original_market, original_asset_class, original_frequency, long_short, entry_rules, exit_rules, position_sizing, stop_loss, take_profit, holding_period, rebalance_frequency, required_data, translation_notes. Some entries have rule text (entry_rules etc.); most (source 'pwb_papers') have only a paper title.
The LLM client: `from llm import get_provider; from llm import provider as prov`. provider.complete(system, user, max_tokens=2000, temperature=0.0) returns a Response with .text, .model, .prompt_tokens, .completion_tokens; prov.record(conn, resp, purpose, task_id, rates) logs the call (rates = cfg["ado"]["rates"]). Tests pass a fake provider object with a complete() method returning an object with those attributes; record must be skipped when the provider has no real model (call it inside try/except).
Genome grammar (JSON): a genome is {"entry": NODE, "exit": NODE, "risk": {"stop_atr_multiple": float, "max_hold_days": int}}. A NODE is one of {"col": NAME}, {"const": number}, {"op": OP, "args": [NODE, ...]} and for time-series ops also "n": int. OPs: comparisons "gt","lt","crosses_above","crosses_below" (2 args); logic "and","or" (2 args), "not" (1 arg); time-series within a ticker "lag","delta","zscore","pct_change" (1 arg + n); cross-sectional "rank" (1 arg, percentile 0-1 across stocks that day). Positions are long only, one stock per position, $20 each; a rule "buy the top decile of X" is gt(rank(col X), const 0.9). An exit that never fires is {"op":"lt","args":[{"col":"close"},{"const":0}]} (exit by stop or holding period only).
Allowed column names: close, volume, returns, dollar_volume_20, the technical features sma_50 sma_200 rsi_14 roc_10 adx_14 macd macd_signal macd_hist bb_pct vol_ratio price_above_sma50 price_above_sma200 golden_cross atr_14 stoch_k stoch_d obv_rising cci_20 willr_14 chaikin_osc pct_of_52w_high pct_off_52w_low drawdown_200 log_dollar_volume, the panel columns piotroski_f book_to_market gross_profitability chs_distress asset_growth accruals roa earnings_yield net_share_issuance debt_to_equity cash_to_assets altman_z fcf_to_price rd_to_assets market_cap sue sue_age alpha_252 short_volume_ratio_20 analog_p_up analog_mean analog_q10 composite insider_buy_usd_90 insider_buyers_90 opp_buyers_90, and calendar columns cal_month cal_dom cal_tdom cal_tdom_rev cal_pre_holiday cal_post_holiday. Data we hold: US stocks and ETFs, daily bars from 1962, SEC fundamentals; NOT forex, futures, commodities, crypto (for this factory), options, intraday bars, analyst estimates, news.
Families (use exactly one): MOMENTUM TREND MEAN_REVERSION VALUE QUALITY LOW_VOLATILITY SIZE REVERSAL EARNINGS_SURPRISE ANALYST_REVISION SEASONALITY BREAKOUT VOLATILITY LIQUIDITY PAIRS RELATIVE_VALUE FACTOR REGIME EVENT FUNDAMENTAL HYBRID OTHER.

## Requirements
1. FIELDS = ("universe","entry","exit","ranking","lookback","holding_period","rebalance","position_sizing","long_short","stop","take_profit","risk_rules","required_data","regime_filter","liquidity"). UNSTATED = ("unspecified","unknown","requires_interpretation"). FAMILIES = the 22 names above. ALLOWED_COLS = the column names above (a tuple). PROMPT_VERSION = "1".
2. init(conn): CREATE TABLE IF NOT EXISTS knowledge_translations(entry_id TEXT PRIMARY KEY, translated_at TEXT, model TEXT, prompt_version TEXT, original_definition TEXT, fields TEXT, genome TEXT, assumptions TEXT, ambiguities TEXT, missing_information TEXT, translation_confidence REAL, machine_translatable TEXT, family TEXT, data_available TEXT, errors TEXT) — JSON text for fields/genome/assumptions/ambiguities/missing_information/errors.
3. original_definition(entry: dict) -> str: the source's own words, assembled from the non-empty entry columns listed in Background as "label: value" lines (title always first). This is stored verbatim and never altered.
4. build_prompt(entry: dict) -> (system, user): the system prompt states the rules: extract only what the source states; every field in FIELDS gets the source's wording or one of UNSTATED; never invent a number the source does not give; the genome is a Stockbot INTERPRETATION and may fill gaps only with assumptions it lists; if the strategy needs data we do not hold, genome is null and data_available is "NO" with the reason; answer with ONE JSON object in a ```json fenced block with keys fields, genome, assumptions, ambiguities, missing_information, translation_confidence (0..1), family, data_available ("YES"/"NO: reason"). It includes the grammar, the allowed columns and the families from Background. The user message is original_definition(entry).
5. validate_genome(g) -> list[str] of errors: [] for a valid genome; errors for a missing entry/exit/risk, an unknown op, wrong arg count, a col not in ALLOWED_COLS, a time-series op without an integer n in 1..504, a const that is not a finite number, stop_atr_multiple outside 0.5..10, max_hold_days outside 1..504. Recursive.
6. parse_response(text) -> dict: take the first ```json fenced block (or the whole text if none), json.loads it; missing FIELDS are filled with "unspecified"; family not in FAMILIES becomes "OTHER"; translation_confidence clamped to 0..1 (default 0); errors = validate_genome(genome) when genome is not null; machine_translatable = "NO" when genome is null or has errors, "PARTIAL" when any of entry/exit/holding_period/universe is in UNSTATED, else "YES". Unparseable text -> dict with errors ["unparseable response"], machine_translatable "NO", genome None.
7. translate(conn, provider, entry: dict, rates=None) -> dict: prompt, complete, parse, INSERT OR REPLACE into knowledge_translations (translated_at UTC ISO, model = resp.model), record the call (purpose "knowledge_extract", task_id entry_id) when rates is given; return the parsed dict.
8. pending(conn, limit=50, sources=None) -> list[dict]: knowledge_entries rows with no knowledge_translations row, entries with entry_rules text first, then the rest by entry_id; optional source filter.
9. run(conn, provider, limit=50, sources=None, rates=None) -> dict counts {"translated": n, "yes": n, "partial": n, "no": n, "errors": n}; a provider exception on one entry is logged and counted in errors, and the loop continues.
10. main(argv=None): --run [--limit 50] [--source NAME ...], --status (counts by machine_translatable and family). Uses sqlite3.connect(load_config()["database"]["market_data_path"], timeout=60), row_factory sqlite3.Row, get_provider(cfg), rates cfg["ado"]["rates"]. Import runtime first.
